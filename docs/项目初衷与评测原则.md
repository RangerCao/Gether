# 项目初衷与评测原则

> 本文件是 Gether 后续算法、检索、排序、选片和研报生成的准入标准。
> 当局部优化与本文冲突时，以本文为准。

---

## 一、项目初衷

Gether 面向的是想要获取**可靠、综合信息**的用户：

> 用户不需要自己逐个刷视频、记时间点、对比观点；
> Gether 从尽可能广的社交媒体视频中收集证据，
> 用尽量少的时间，生成覆盖全面、可靠、忠于原视频内容的研报。

核心价值不是“选片 Precision 最高”，而是：

```text
覆盖广 + 来源可靠 + 观点多元 + 引用忠实 + 节省时间
```

---

## 二、五个优化目标

| 维度 | 目标 | 代表指标 |
|---|---|---|
| 覆盖 | 不遗漏重要主题、来源、立场 | facet/source/stance coverage，相关视频 Recall |
| 可靠 | 证据来源可信、可核验 | 权威来源比例、证据有效率、冲突发现率 |
| 忠实 | 研报不歪曲原视频 | claim 支持率、引用准确率、时间戳准确率、无支撑 claim 率 |
| 效率 | 用户少花时间 | 选片时长、解析成本、端到端耗时 |
| 用户价值 | 研报真正可用 | 人工可用性评分、决策帮助度 |

排序、选片、权重都只是实现这些目标的手段。

---

## 三、明确不做的事

- 不为少数问题类型写死硬门控；
- 不用 9 个问题反复调参后宣称泛化；
- 不把“决策型/权威型”当成固定模板直接过滤内容；
- 不为了 Precision 牺牲覆盖和反方信息；
- 不用没有证据的内容填充研报；
- 不把播放量当成权威性本身。

---

## 四、排序与选片原则

### 4.1 意图是特征，不是硬门控

用户问题千差万别，系统可以识别：

```text
意图 / 问题类型 / 时间约束 / 来源偏好 / 决策属性
```

但这些应作为**排序特征或弱先验**，而不是：

```text
识别为决策型 → 只允许某几类视频
识别为权威型 → 只允许官方视频
```

硬约束只保留：

- 用户显式指定的约束；
- 安全/合规；
- 没有证据的内容不能进入研报。

### 4.2 先资格，后排序，再集合优化

```text
1. 基础资格：主题、语言、时长、重复、安全
2. 通用排序：相关性、权威、时效、内容质量、来源
3. 集合优化：覆盖、多样性、反方、预算
```

不要把所有约束塞进一个加权分数。

### 4.3 权威与内容类型是特征

内容类型、官方/研究属性、credibility 可以作为排序特征，但不应该单独决定“某类问题只能选某类内容”。

### 4.4 选片是预算内的覆盖问题

目标不是 Top-K，而是：

```text
在解析预算内最大化主题/来源/立场覆盖
- 冗余
- 时长成本
```

## 五、评测原则

### 5.1 广泛问题集

评测集必须覆盖：

```text
科技 / 产品 / 健康 / 财经 / 政策 / 生活 / 人物 / 行业 / 教育
```

不能只覆盖 AI 编程、汽车、Java 等当前失败样本。

### 5.2 分层与留出

- 回归集：当前 9 个问题；
- 广泛集：40–60 个问题；当前 `eval/datasets/discovery_broad_questions.json` 有 48 题，已标注 48 题；当前选中集 Top-10 Recall 约 0.384。
- Holdout：6–10 个未参与设计的问题；
- 按主题/时间分层，避免数据泄漏。

### 5.3 不是只看 Precision

至少同时报告：

```text
Precision
Recall
nDCG
Facet / Source / Stance Coverage
False Positive
Duration / Cost
```

最终还要看：

```text
研报 claim 支持率
引用准确率
时间戳准确率
无支撑 claim 率
```

### 5.4 消融实验

每次引入新机制，必须做：

```text
Baseline
+ 机制 A
+ 机制 B
+ 全部
```

只有满足以下条件才保留：

```text
Precision 提升 ≥ 0.03
Recall 下降 ≤ 0.05
覆盖率不下降
成本不显著上升
```

否则回退。

### 5.5 小样本处理

- 逐问题报告，不只报告平均值；
- 使用配对比较；
- 用 bootstrap 估计置信区间；
- 明确区分“方向性结果”和“统计显著结果”。

---

## 六、研报忠实度

“忠于原视频”必须独立评测：

| 指标 | 含义 |
|---|---|
| Claim Support Rate | 有 evidence 支持的 claim 比例 |
| Citation Precision | 引用确实支持 claim 的比例 |
| Citation Recall | 关键 claim 都有引用的比例 |
| Timestamp Accuracy | 时间戳对应片段是否真的包含该内容 |
| Unsupported Claim Rate | 无证据 claim 比例 |
| Contradiction Coverage | 发现并呈现的反方/冲突比例 |

排序优化不能替代忠实度评测。

---

## 七、当前架构约束

- Discovery 与 Evidence Retrieval 分离；
- 主题/内容类型/意图只作为通用特征；
- 不为单一问题类型新增全局硬过滤；
- 新方案先在广泛评测集和 holdout 上验证；
- 局部修复必须能解释为通用机制，不能只对样例有效。

---

## 八、决策记录

| 决策 | 结论 |
|---|---|
| 意图硬门控 | 不继续扩展；已有局部硬门控移除 |
| 通用排序 | 优先做统一特征与基线，而非问题类型模板 |
| 评测 | 广泛集 + holdout + 消融，不只 9 问题 |
| 研报目标 | 覆盖、可靠、忠实、省时，而非单一 Precision |
| 权重调优 | 门控稳定后，在独立数据上按 profile 调 |
