# 任务状态与错误链路设计

> 目标：从 Python 实际处理步骤，到 Java 治理层，再到前端展示，形成一条可追踪、可重放、带具体错误原因的状态链路。
>
> 本文覆盖：
>
> - 解析阶段：`PENDING → PARSING → PLANNING`
> - 研报阶段：`PLANNING → GENERATING → DONE / FAILED`
> - 解析 SSE、研报 SSE、Java callback、HMAC、前端展示
> - 每种错误码对应的后端代码位置

---

## 一、总链路

```text
Python executor
  ParseService / IngestPipeline / ReportService
        │
        │  阶段事件 + HMAC callback
        ▼
Java governor
  CallbackController
        │
        ├── TaskService.applyCallback
        │       ├── 更新任务状态 / error_code / error_message
        │       └── SseHub.publish
        │
        ▼
  SseHub（内存 replay + heartbeat）
        │
        │  text/event-stream
        ▼
React frontend
  App.tsx（解析状态 / stage / 错误）
  ReportWorkspace.tsx（研报 state / token / error）
```

## 三、解析阶段事件

### 3.1 Python 发送位置

文件：

```text
services/executor/app/services/parse_service.py
```

函数：

```text
parse_task()
  notify()
  on_progress()
```

`notify()` 通过 `CallbackClient.send()` 发送：

```json
{
  "event": "stage",
  "seq": 3,
  "payload": {
    "status": "PARSING",
    "stage": "asr",
    "message": "无可用字幕，开始语音转写",
    "progress": 27,
    "video_index": 1,
    "video_count": 8
  }
}
```

### 3.2 阶段与代码对应

| 阶段 | 事件 | Python 位置 | 含义 |
|---|---|---|---|
| `parse_started` | `stage` | `parse_task` 中的 `notify("stage", ...)` | 开始解析整个视频集合 |
| `subtitle` | `stage` | `IngestPipeline.parse_video.emit("subtitle", ...)` | 尝试原生字幕 |
| `asr` | `stage` | `IngestPipeline.parse_video.emit("asr", ...)` | 无字幕后语音转写 |
| `ocr` | `stage` | `IngestPipeline.parse_video.emit("ocr", ...)` | 关键帧 OCR |
| `video_done` | `video_parsed` | `parse_task` 中 `notify("video_parsed", ...)` | 单个视频解析完成 |
| `video_failed` | `video_failed` | `parse_task` 的异常分支 | 单个视频失败，但继续其他视频 |
| `no_evidence` | `parse_failed` | `parse_task` 的 `evidence_count == 0` 分支 | 所有视频都没有证据 |
| `internal_error` | `parse_failed` | `parse_task` 的外层 `except` | 未预期异常 |
| `parse_finished` | `parse_finished` | `parse_task` 成功分支 | 全部视频完成，进入 `PLANNING` |

### 3.3 解析事件 payload

通用字段：

| 字段 | 说明 |
|---|---|
| `status` | `PARSING` / `FAILED` / `PLANNING` |
| `stage` | 当前阶段 |
| `message` | 面向用户的中文说明 |
| `progress` | 0–100 |
| `video_index` | 当前第几个视频，从 1 开始 |
| `video_count` | 总视频数 |
| `evidence_count` | 已完成证据数 |
| `code` | 错误码，仅失败事件 |
| `detail` | 具体异常信息 |
| `url` | 失败视频 URL |
| `failures` | 多视频失败明细 |

### 3.4 成功解析事件序列

```text
stage parse_started
stage subtitle
stage asr
video_parsed video_done
stage subtitle
stage asr
video_parsed video_done
...
parse_finished
```

前端展示：

```text
正在解析 · 第 2/8 个视频 · 无可用字幕，开始语音转写
```

### 3.5 单视频失败但仍有其他证据

```text
video_failed
  code=DOWNLOAD_FAILED
  detail=下载失败：...
  url=https://www.bilibili.com/video/BV...
```

任务继续处理后续视频。

### 3.6 所有视频无证据

```text
parse_failed
  code=NO_EVIDENCE
  message=没有可用的视频证据
  failures=[...]
```

Java：

```text
TaskService.applyCallback
  case "parse_failed"
  → task.status = FAILED
  → task.error_code = payload.code
  → task.error_message = payload.message
```

## 五、Java 状态桥

### 5.1 CallbackController

文件：

```text
services/governor/src/main/java/com/gether/governor/api/CallbackController.java
```

职责：

- 校验 `X-Timestamp` / `X-Signature` HMAC；
- 解析 `{event, seq, payload}`；
- 调用 `TaskService.applyCallback`。

### 5.2 TaskService.applyCallback

文件：

```text
services/governor/src/main/java/com/gether/governor/service/TaskService.java
```

事件到任务状态的映射：

| Python event | Java 任务状态 | 来源 |
|---|---|---|
| `parse_finished` / `planning` | `PLANNING`，progress 90 | `TaskService.applyCallback` |
| `parse_failed` | `FAILED`，progress 100 | `TaskService.applyCallback` |
| `generation_done` | `DONE`，progress 100 | `TaskService.applyCallback` |
| `generation_failed` | `FAILED`，progress 100 | `TaskService.applyCallback` |
| 其他 `stage` / `video_parsed` / `video_failed` / `state` / `token` / `conflict` / `citation` | 不改主状态，直接 publish SSE | `TaskService.applyCallback` 的 `default` |

### 5.3 SseHub

文件：

```text
services/governor/src/main/java/com/gether/governor/sse/SseHub.java
```

能力：

- 每任务独立 channel；
- 每事件自增 `id`；
- 内存 replay buffer；
- 支持 `Last-Event-ID` 续传；
- 15 秒心跳；
- 慢消费者自动 detach。

### 5.4 幂等

数据库表：

```text
task_callbacks(task_id, event_type, seq)
```

唯一约束：

```text
(task_id, event_type, seq)
```

重复 callback 只入库一次，不重复推进状态。

## 六、前端展示

### 6.1 App.tsx

文件：`services/web/src/App.tsx`

SSE 处理：

```text
streamTaskEvents()
  ├── stage            → 更新 stageMessage
  ├── video_failed     → 显示具体失败信息
  ├── parse_failed     → setError(code + message)
  ├── parse_finished   → 进入 PLANNING
  └── status=FAILED    → 显示失败
```

轮询兜底：

```text
api.getTask(taskId)
  ├── PENDING/PARSING → 每 2s 轮询
  ├── PLANNING        → 自动进入研报
  └── FAILED          → 展示 error_code/error_message
```

`PARSE_INTERRUPTED`：

```text
自动重试一次 parseTask()
```

实现：`App.tsx` 的 `poll()` / `autoRetried`。

### 6.2 ReportWorkspace.tsx

文件：`services/web/src/ReportWorkspace.tsx`

```text
handleGenerate()
  ├── reportApi.streamResume()
  ├── state/token/conflict/citation/done → 更新 UI
  ├── error → setError(message)
  └── SSE 失败 → reportApi.resume() 同步回退
```

## 七、错误码总表

### 7.1 任务执行错误

| 错误码 | 触发代码 | 说明 | 用户看到 |
|---|---|---|---|
| `PARSE_INTERRUPTED` | `app/repository.py:fail_parsing_tasks` | 执行层重启，残留 PARSING 被标记失败 | `执行层重启，解析任务已中断` |
| `EXECUTOR_UNAVAILABLE` | `TaskService.trigger` / `ExecutorHealthMonitor` | Java 调 Python 失败或健康检查失败 | `AI 执行层暂不可用` |
| `NO_EVIDENCE` | `ParseService.parse_task` / `IngestPipeline.parse_video` | 所有视频均无证据 | `没有可用的视频证据` |
| `INTERNAL_ERROR` | `ParseService.parse_task` 外层 `except` | 未预期异常 | 具体异常字符串 |
| `PARSE_FAILED` | `ParseService.parse_task` 的 `getattr(exc, "code", ...)` | 单视频异常兜底 | 具体 message |
| `REPORT_FAILED` | `ReportService._safe_fail` | Writer/Adjudicate 异常 | 研报生成失败原因 |

### 7.2 单视频/媒体错误

| 错误码 | 代码位置 | 说明 |
|---|---|---|
| `INVALID_URL` | `ingest/sources/bilibili.py` / `local.py` / `youtube.py` / `base.py` | URL 不合法或不支持 |
| `VIDEO_TOO_LONG` | `ingest/sources/base.py` | 视频超过限制 |
| `SOURCE_ERROR` | `ingest/sources/base.py` | 源适配器通用错误 |
| `DOWNLOAD_FAILED` | `ingest/downloader.py` | 音频/视频下载失败 |
| `ASR_FAILED` | `ingest/asr.py` | 语音转写不可用/失败 |
| `OCR_FAILED` | `ingest/ocr.py` | OCR 不可用/失败 |
| `FRAME_EXTRACTION_FAILED` | `ingest/frames.py` | ffmpeg/关键帧抽取失败 |
| `STORAGE_FAILED` | `core/storage.py` | 媒体存储失败 |

说明：ASR/OCR/FRAME 失败通常被 `IngestPipeline` 捕获为 warning，继续其他模态；只有最终没有任何证据才会变成 `NO_EVIDENCE`。

### 7.3 发现阶段错误

| 错误码 | 代码位置 | 说明 |
|---|---|---|
| `SEARCH_FAILED` | `app/discovery/search.py:SearchError` | B站/YouTube 搜索失败 |
| `DISCOVERY_FAILED` | `app/api/routes.py` / `DiscoveryError` | Discovery 编排失败 |
| `SESSION_NOT_FOUND` | `api/routes.py` | 发现会话不存在 |
| `DISCOVERY_DISABLED` | `api/routes.py` | Discovery 未启用 |

### 7.4 Java API 错误

| 错误码 | 代码位置 | HTTP |
|---|---|---|
| `INVALID_INPUT` | `ApiExceptionHandler.validation` | 400 |
| `TASK_NOT_FOUND` | `ApiExceptionHandler.notFound` | 404 |
| `QUOTA_EXCEEDED` | `ApiExceptionHandler.quota` | 429 |
| `EXECUTOR_UNAVAILABLE` | `ApiExceptionHandler.executor` | 503 |
| `NOT_FOUND` | `ApiExceptionHandler.status` | 404 |
| `REQUEST_FAILED` | `ApiExceptionHandler.status` | 其他 4xx |

## 九、可靠性保证与限制

### 保证

- HMAC 校验 callback；
- `(task_id,event,seq)` 幂等；
- SSE `id` + `Last-Event-ID` 重放；
- 15 秒 heartbeat；
- App 轮询兜底；
- `PARSE_INTERRUPTED` 自动重试一次；
- SSE 失败时研报切同步 `/resume`。

### 限制

- Java `SseHub` replay 是内存态，Java 重启后旧任务事件不能 replay；
- Python callback 失败只记录 warning，不保证一定送达；
- 前端轮询是最终一致性兜底；
- 目前研报 `error` 只有 message，没有细分到具体 Writer 子步骤；
- 单视频失败不会让整个任务失败，只有无证据时才失败。
