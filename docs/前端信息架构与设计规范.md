# 前端信息架构与设计规范

> 本文是 Gether 完整前端页面的设计基线。
>
> 当前前端是“可测试工作台”，不是最终产品形态。本文先冻结信息架构、页面结构、状态矩阵和组件规范，等后端契约与研报质量验收通过后再进入完整施工。

---

## 一、设计目标

### 1.1 用户目标

用户不是来“操作一个 Agent”，而是来：

```text
提出一个研究问题
→ 等待系统自动完成检索/解析/研报
→ 阅读可追溯的研报
→ 点击引用查看原片证据
→ 看到冲突与不同来源
```

前端应让用户始终知道：

```text
系统现在在做什么
已经完成了什么
为什么失败
哪些结论有证据
哪些地方存在分歧
```

### 1.2 设计原则

- **自动优先**：默认自动选片、解析、生成研报。
- **可解释**：每个阶段、每个分数、每个引用都能解释。
- **可恢复**：失败有明确阶段、原因和重试入口。
- **证据优先**：引用、时间戳、原片播放是核心交互。
- **不隐藏复杂度**：高级信息可折叠，但不能只有黑盒结论。

## 三、页面地图

```text
/                         研究首页
/tasks                    任务列表 / 历史
/tasks/:taskId            研究工作台
/reports/:taskId          研报阅读页
/settings                 数据源 / 模型 / 偏好
```

### 3.1 研究首页 `/`

```text
┌────────────────────────────────────────────┐
│ Gether        [任务] [设置]       [连接状态] │
├────────────────────────────────────────────┤
│                                            │
│  提出一个值得研究的问题                     │
│  ┌──────────────────────────────────────┐  │
│  │ AI 编程工具真的能提升开发效率吗？      │  │
│  └──────────────────────────────────────┘  │
│  [开始研究]                                │
│                                            │
│  最近任务                                   │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐      │
│  │ DONE    │ │ PARSING │ │ FAILED  │      │
│  └─────────┘ └─────────┘ └─────────┘      │
└────────────────────────────────────────────┘
```

关键点：

- 首页只保留一个问题输入和最近任务。
- 不在这里堆检索参数。
- 默认自动模式。
- 高级选项折叠在“研究设置”。

### 3.2 任务列表 `/tasks`

```text
┌────────────────────────────────────────────┐
│ 任务                                        │
│ [全部] [进行中] [完成] [失败]                │
├────────────────────────────────────────────┤
│ 问题                    状态    进度  证据   │
│ AI 编程工具真的能...    DONE    100%  1009  │
│ 人生第一辆车...          FAILED  100%  483   │
└────────────────────────────────────────────┘
```

- 支持按状态筛选。
- 点击进入 `/tasks/:id`。
- 失败任务直接显示错误码。

### 3.3 研究工作台 `/tasks/:taskId`

核心页面，建议三栏：

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ Agent 轨迹    │ 主工作区                      │ 证据 / 冲突       │
│              │                              │                  │
│ ✓ 检索        │ 当前阶段：解析 3/8            │ 证据播放器        │
│ ✓ 选片        │ [进度条]                      │                  │
│ ● 解析        │                              │ 当前引用          │
│ ○ 生成研报    │ 候选视频                      │ 冲突列表          │
│              │ 或研报正文                    │                  │
│ 错误/重试     │                              │ 质量指标          │
└──────────────┴──────────────────────────────┴──────────────────┘
```

#### 左栏：Agent 轨迹

```text
检索
选片
解析
索引
大纲
研报
裁决
```

每个节点：

- 状态：等待 / 运行 / 完成 / 失败 / 跳过
- 耗时
- 关键输出数量
- 失败时的错误码和阶段

#### 中栏：主工作区

按阶段切换：

1. **检索中**：查询计划、facet、候选数量
2. **已选片**：候选视频卡（自动选中）
3. **解析中**：当前视频、阶段、证据数
4. **研报生成**：大纲 + 正文流式生成
5. **完成**：研报正文

#### 右栏：证据与冲突

- 视频播放器
- 当前引用原文
- 冲突卡
- 质量指标：
  - claim 支持率
  - 引用合法率
  - 来源数
  - 冲突数

### 3.4 研报阅读页 `/reports/:taskId`

```text
┌────────────────────────────────────────────┐
│ 研报标题 / 状态 / 导出                      │
├───────────────────────────┬────────────────┤
│ 正文                       │ 证据侧栏        │
│                           │ 播放器          │
│ [1] 引用                   │ 引用原文        │
│                           │ 冲突            │
└───────────────────────────┴────────────────┘
```

- 正文优先，阅读宽度限制。
- 引用角标点击打开右栏播放器。
- 移动端变成“正文 + 底部播放器抽屉”。

### 3.5 设置 `/settings`

```text
数据源
  B站 [开]
  YouTube [关，网络不可用]

模型
  DeepSeek
  DashScope

研究默认值
  最多视频 8
  时长预算 180 分钟
  自动选片 [开]
```

API Key 不出现在前端；只显示“已配置/未配置”。

## 四、状态矩阵

### 4.1 任务状态

| 状态 | 页面表现 | 主操作 |
|---|---|---|
| `PENDING` | 准备中 | 等待 |
| `PARSING` | 当前视频/阶段/进度 | 可取消（后续） |
| `PLANNING` | 大纲生成中 | 自动继续 |
| `GENERATING` | 章节流式生成 | 自动继续 |
| `DONE` | 研报 + 引用 | 阅读/导出 |
| `FAILED` | 错误详情卡 | 重试 |
| `CANCELLED` | 已取消 | 重新发起 |

### 4.2 错误详情卡

```text
┌────────────────────────────────────┐
│ DOWNLOAD_FAILED       阶段 video    │
│ 第 2/8 个视频解析失败               │
│ 详细：下载失败：HTTP 412           │
│ 失败视频：BV...                     │
│ [重试解析] [查看日志]               │
└────────────────────────────────────┘
```

必须包含：

- 错误码
- 阶段
- 任务 ID
- 可读原因
- 原始 detail
- 失败视频 URL
- 重试入口

### 4.3 空状态

```text
没有检索到候选视频
没有可用证据
研报没有足够证据
索引尚未建立
```

每个空状态必须给下一步建议。

## 八、交互规则

### 8.1 自动流程

- 用户点击一次“开始研究”。
- 检索后自动选片。
- 自动创建任务。
- 自动解析。
- 自动生成大纲。
- 自动生成研报。

用户唯一必须做的是：

```text
提出问题 → 阅读结果
```

### 8.2 可干预点

默认不打断，但提供：

- 查看候选视频
- 修改大纲（生成前）
- 失败重试
- 手动补充视频（后续）
- 导出研报（后续）

### 8.3 SSE 断线

```text
自动重连
→ Last-Event-ID 续传
→ 失败则轮询
→ 显示“正在恢复连接”
```

## 十、验收标准

```text
用户只输入问题，不需要手动选片/解析/生成
任何失败都能看到错误码 + 阶段 + 详情
任何引用都能打开原片
移动端可读研报
SSE 断线能恢复
空研报/索引竞态不再出现
```

达到以上条件后，再进入完整前端施工。
