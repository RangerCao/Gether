# 项目架构选型说明：Java + FastAPI 双栈架构设计

## 一、 为什么选择双栈架构？

在构建面向 AI Agent 的深度研报生成系统时，面临的核心矛盾是：**AI 推理的极度不确定性、高耗时与前端高并发请求、状态强一致性之间的冲突。**

单一使用 FastAPI 从头写到尾会导致 Python 主线程（Event Loop）极易被阻塞，且缺乏企业级的容灾与状态治理能力。因此，项目采用 **Java（治理层） + Python/FastAPI（执行层）** 的异构架构，实现业务逻辑与 AI 推理的彻底解耦。

## 二、 核心职责划分

| 层级 | 技术栈 | 核心职责 | 技术选型依据 |
| :--- | :--- | :--- | :--- |
| **治理层** | Java / Spring Boot | 1. 高并发 SSE 长连接管理<br>2. 任务状态机流转与强一致性<br>3. 统一鉴权、限流、熔断降级<br>4. 异步任务调度与事件分发 | 处理高并发、强事务和线程调度是 Java 的统治区。利用 JDK 21 虚拟线程可轻松支撑海量连接。 |
| **执行层** | Python / FastAPI | 1. 音视频双轨解析（ASR/OCR）<br>2. RAPTOR 树状索引与混合检索<br>3. LangGraph 状态机编排与 Prompt 拼装<br>4. LLM 交互与流式生成 | Python 拥有最完善的 AI 生态（LangChain、faster-whisper 等），只做纯无状态的 AI 执行器，不给 Python 增加多余的并发与鉴权负担。 |

## 三、 为什么不用 FastAPI 从头写到尾？（核心痛点）

### 1. 突破 GIL（全局解释器锁）的阻塞陷阱
*   **单栈痛点**：Python 在处理 CPU 密集型任务（如 Whisper 语音转写）时，GIL 会导致事件循环阻塞。此时前端发起的 SSE 请求（查看进度）会直接卡死或超时。
*   **双栈优势**：Java 作为高可用前置网关，利用多线程/虚拟线程死死抗住前端的数千个 SSE 长连接，后台 AI 算得再慢，Java 也能稳定向用户下发“正在生成中”的心跳包，保障用户体验。

### 2. 解决“一损俱损”的容灾隔离
*   **单栈痛点**：大模型 API 经常超时或 OOM（内存溢出）。如果 FastAPI 一肩挑，AI 服务一崩溃，整个网站直接瘫痪，用户甚至连历史记录都查不了。
*   **双栈优势**：Java 层（BFF 层）实现了物理隔离。哪怕底层 Python AI 服务全面崩溃，Java 依然能存活，并通过熔断降级策略，给前端返回“当前排队人数过多，请稍候”的友好提示。

### 3. 保障业务状态的绝对强一致
*   **单栈痛点**：长流程任务涉及复杂的排队、解析、人工确认、失败重试。用 Python 写复杂的状态机和事务控制极其繁琐且易出错。
*   **双栈优势**：利用 Spring 的 `@Transactional` 保证任务状态流转与计费扣减的原子性。Python 彻底沦为无状态执行器（Stateless Worker），极大降低了 AI 开发的心智负担。

## 四、 面试防守反击话术（Q&A）

**Q1：面试官质疑：“就为了个 SSE 和状态机搞两个服务，是不是过度设计？为了用 Java 而用 Java？”**
> **你的回答（降维打击）**：“如果只做 Demo，全用 FastAPI 确实最快。但这并非儿戏，而是有意识地在模拟真实的企业级架构。在互联网大厂，AI 团队只交付 Python 的模型服务，而前端业务侧全是 Java。我这样做，一是为了实践多语言异构架构的通信与联调；二是为了解决 Python GIL 导致 SSE 阻塞的真实痛点。Java 负责抗并发管状态，Python 负责跑模型，这是架构上的优势互补。”

**Q2：面试官提问：“Java 层为什么不直接用 LangChain4j 做 AI 逻辑？”**
> **你的回答**：“术业有专攻。Java 生态在 Prompt 工程、复杂 RAG 检索和向量库集成上，远不如 Python 成熟。强制用 Java 写 AI 逻辑是在给自己挖坑。我的原则是：**Java 做厚业务边界，Python 做深 AI 执行**。”

## 五、 简历包装提炼（直接可用）

> **异构微服务架构设计**：采用 **Spring Boot（治理层） + FastAPI（AI 执行层）** 双栈架构。利用 Java 21 虚拟线程承担高并发 SSE 长连接管理与任务状态机流转，通过 HTTP 异步调用 Python 侧执行多模态解析与 LangGraph 编排。实现了业务治理与 AI 推理的完美解耦，保障了系统在 LLM 长耗时场景下的高可用与容灾隔离。
