## 五、P2：分块、Embedding 与混合检索

### [P2-001] 2026-11-11 01:05 检索选型与首批实现

- 阶段：P2
- 类型：决策 + 迭代
- 背景：证据已是 5 秒级切片，直接检索粒度过细。
- 决策：
  - 分块目标 360 字符 / 上限 480 / 重叠 60；
  - Embedding 用 `BAAI/bge-small-zh-v1.5`（512 维，FastEmbed ONNX），避免 bge-m3 的体积与首载延迟；
  - BM25 用 jieba + `rank_bm25`，与向量路做 RRF。
- 实现：`app/index/{chunking,embedding,bm25,retrieval,service,repository}.py`；新增 `chunks` 表与 HNSW 索引。
- 验证：单元测试覆盖分块、中文分词、RRF、向量+BM25 融合。

### [P2-002] 2026-11-11 01:06 三个实现级 Bug

- 阶段：P2
- 类型：问题
- 现象/原因：
  1. BM25 分词正则只匹配单个汉字，`杭州` 被切成 `杭`，召回为空。
  2. 分块强制 `target_chars >= 80`，小规模测试无法验证目标长度；且 overlap 逻辑可能产生只含 carry 的重复块。
  3. 测试语料只有 1 个 chunk，BM25 的 IDF 为 0，导致 `bm25_rank=None`。
- 处理：正则改 `[一-鿿]+`；下限降为 20 并在 flush 中跳过 carry-only 块；评测语料扩充到 24 条 query / 多 chunk。
- 验证：`test_bm25_rrf.py`、`test_chunking.py`、`test_retrieval.py` 通过。

### [P2-003] 2026-11-11 01:10 索引接口与 pgvector

- 阶段：P2
- 类型：迭代
- 内容：
  - `chunks` 表：`embedding vector(512)` + HNSW；
  - `POST /internal/tasks/{id}/index`、`GET /internal/tasks/{id}/chunks`、`POST /internal/retrieve`；
